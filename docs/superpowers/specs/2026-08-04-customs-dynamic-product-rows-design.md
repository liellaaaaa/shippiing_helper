# 报关资料按产品数动态扩展设计

日期: 2026-08-04
状态: 待审阅

## 1. 背景与问题

用户反馈：生成报关资料时，报关单最多只能写入约 5-6 个产品。实际业务中常有 8-9 个甚至十几个产品，需要支持按数据量自动往下新增产品行。

## 2. 根因分析（已实测确认）

限制不是代码写死，而是模板文件 `references/出口报关资料-模板.xlsx` 的**报关单 sheet 预建结构**：

- 报关单 sheet 每个产品占 **3 行**（数据行 / 申报要素行 / 币制行），起始行 20
- 模板预建到第 **37 行**（共 6 块 = 6 个产品），行 38 之后无任何样式/合并/边框
- 打印区域 `'报关单'!$A$1:$S$37` 也止于第 37 行
- 代码 `document_service.py:985` 计算 `max_items = (ws.max_row - 20) // 3`，`:994` 处 `row + 2 > ws.max_row` 截断，超出部分被静默丢弃（仅 warning 日志）

| Sheet | 预建产品容量 | 产品行结构 |
|-------|------------|-----------|
| 报关单 | **6 个**（行 20-37，每品 3 行） | 数据行/申报要素行/币制行，含合并单元格+边框 |
| 发票 | 16 个（行 8-23），汇总行 24 | 每品 1 行，A:B 合并 |
| 箱单 | 16 个（行 10-25），汇总行 26 | 每品 1 行，含 SUM 公式与 OFFSET 引用 |

发票/箱单容量足够（16 个），瓶颈只在报关单。

## 3. 需求确认（用户已确认）

1. **不预先扩展模板文件** —— 模板保持只读，用不到那么多行时不想浪费
2. **生成时按数据量自动往下新增行** —— 有 8 个产品就出 8 块，有 20 个就出 20 块，无上限限制
3. **只扩展报关单 sheet** —— 发票/箱单维持模板现有 16 行容量，本次不动

## 4. 方案选择

| 方案 | 说明 | 结论 |
|------|------|------|
| A. 代码动态扩展 | 生成时若 N > 6，从第 38 行起按 3 行/块复制样式/合并/边框/行高，模板文件零改动 | **采纳**（用户选定） |
| B. 直接扩展模板 | 一次性把模板扩到 16/20 块 | 用户拒绝（浪费） |
| C. 折中 | 模板扩到 16 + 超出再动态扩展 | 未采纳 |

## 5. 详细设计

### 5.1 扩展规则

在 `DocumentService.generate_customs` 中，产品数 N（过滤子项后的 `doc_items` 数量）决定报关单块数：

- N ≤ 6：输出与现状完全一致，不触发任何扩展逻辑
- N > 6：以模板第 6 块（行 35-37）为**样式源块**，从第 38 行起逐块复制，共 (N-6) 个新块

### 5.2 块复制内容（每新增一块，目标行 = 38 + k*3, k=0..N-7）

对每个新块，从源块（35/36/37）逐行复制到目标行（target = 38+3k, 39+3k, 40+3k）：

1. **单元格样式**：A..S 列（1-19）逐单元格 `new_cell._style = copy(copy_of_src._style)`（边框/字体/对齐/填充/数字格式）
2. **行高**：`ws.row_dimensions[target].height = ws.row_dimensions[src].height`
3. **合并单元格**：源块涉及的合并区域（如 B35:C35, D35:F35, I35:J35, M35:O35, P35:R35 等）整体偏移 (target-35) 行后 `ws.merge_cells()`，注意申报要素行是跨两行合并（如 D36:F37），偏移后仍保持跨两行
4. **打印区域**：`ws.print_area = "'报关单'!$A$1:$S${20 + 3*N - 1}"`

### 5.3 代码截断点放开

`document_service.py` 中以下硬编码截断改为基于 N：

| 位置 | 现状 | 修改后 |
|------|------|--------|
| `:985` | `max_items = (ws.max_row - 20) // 3`（仅日志用） | 删除截断逻辑，改为正常循环 N 个 |
| `:992-995` | `for idx, item in enumerate(items): row = 20 + idx*3; if row + 2 > ws.max_row: break` | 直接循环 N 个，不再 break |
| `:1057-1071` | T/U/V 辅助列循环 `if helper_row > ws.max_row: break` | 同样放开，按 N 循环 |
| `:1114-1126` | 第二个 T/U/V 辅助列循环（发票后再次写）`if helper_row > ws.max_row: break` | 同样放开，按 N 循环 |

> 注：`ws.max_row` 在扩展后已动态变大，若保留 `break` 判断其实也不会截断；但为清晰起见，将截断判断统一删除，以 N 为准。

### 5.4 不动的部分

- 模板文件 `references/出口报关资料-模板.xlsx`：零改动
- 发票/箱单 sheet 及代码（`:1089` r>23、`:1154` r>25 的 break 保留，维持 16 行容量）
- 合同/委托书 sheet：产品数据靠公式或去重拼接，无行数问题
- 箱单的 OFFSET 公式引用报关单 V 列辅助区：现有公式引用到 V4..V16 对应箱单 16 行，与发票/箱单容量一致，不改

### 5.5 边界与错误处理

- N=0（无产品）：维持现状返回未填充模板
- 样式源块（35-37）在模板中必须存在 —— 模板预建 6 块是硬前提，代码加 `if ws.max_row < 37: raise` 防御
- openpyxl 复制样式用 `copy.copy(cell._style)`，避免浅拷贝共享导致样式串改

## 6. 验证方案

新增后端单元测试（mock 台账数据，不依赖真实文件）：

1. N=5 / N=6：断言报关单块数 = 5/6，无新增行，输出与旧逻辑一致（回归）
2. N=7 / N=10 / N=17：断言
   - 报关单 max_row = 20 + 3*N - 1
   - 每个新块行存在边框（抽样 A/S 列）
   - 每个新块合并单元格数量/位置与源块偏移一致（如申报要素跨两行合并存在）
   - 打印区域 = `$S${20 + 3*N - 1}`
   - 产品数据正确写入（项号、HS Code、数量、单价、币制行）
3. 打印区域更新正确

## 7. 影响范围

- 仅 `backend/app/services/document_service.py`（新增 1 个私有方法 + generate_customs 内调整）
- 新增 1 个测试文件（或扩展现有 document 测试）
- 无数据库/前端/模板改动

## 8. 不做的事（YAGNI）

- 不扩展发票/箱单容量（用户确认不需要，当前 16 行足够）
- 不做用户手动加行的 UI 功能（生成时自动写满即可）
- 不重构 generate_customs 的整体结构，只做最小侵入改动

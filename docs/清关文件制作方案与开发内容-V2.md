## 1. 一句话结论

在「单证生成工作流」的 **报关资料按钮右侧** 新增一组清关单据按钮：

**`订舱补料 SI ｜ 商业发票 CI ｜ 装箱单 PL ｜ 品质证书 COA`**

（产品名统一用「订舱补料 SI」，避免被理解成系统签发提单正本。）

全部以 **PI 合同表为业务源头**，按 **客户编码加载定制模板** 自动填充；  
重量体积 **复用现有 `packaging_service` 的整板/余数三模式**，散货以货代入仓实测覆盖；  
产地证、MSDS、BL 正本不在本期范围。

## 3. 单据体系与字段填写逻辑

### 3.1 数据流

```text
PI（合同表，业务源头）
 ├─ 品名 / 数量 / 单价 / 金额 / 收货人 / 价格术语 / HS
 ├─ CI ◄── + BL 柜封号 + 银行块(可选) + 编号规则 IN
 ├─ PL ◄── + 销售表数量 + packaging 件数体积重量 + BL 柜封号 + 编号规则 PL
 ├─ SI ◄── + 订舱/货代信息（船名航次、柜封、实测）+ 目的港代理
 └─ COA ◄── + 品质部检测报告（含固量/pH/外观）+ 批号日期规则
              批号 SA+YYYYMMDD+序号 → 可解析生产日期
              有效期：按产品规则（+1年-1天 / +6月-1天）或人工
```

### 3.2 数据源优先级（V2 修订：目的地口径）

| 字段 | 权威来源 | 备注 |
|------|----------|------|
| 品名（英文） | **PI** | 不用检测报告中文名直译 |
| 数量 / 净重 | **PI / 销售表** | PL 数量明细可能在销售表 |
| 单价 / 金额 | **PI** | 金额=数量×单价；**币种以系统字段为准**（见 §2.3 反例） |
| 合同号 / PI No | **PI 内容** | 禁止读文件名 |
| 发票号 | 规则生成 | `IN` + 合同号后缀（§3.3） |
| 装箱单号 | 规则生成 | `PL` + 同一后缀 |
| 收货人 / 通知人 | **PI**（可左栏覆写） | 已有 `Phase2Workflow.vue` 覆写 |
| 发货人 / 公司抬头 | **company_code** | honghao / minhao |
| 价格术语 | **PI | 如 CIF HOCHIMINH / CIF KEELUNG |
| **CI/PL ROUTE** | **PI 目的地 → 口径转换** | 见下表 |
| **SI POL/POD** | **订舱/货代（港口级）** | 与 ROUTE 口径可不同 |
| 柜号 / 封号 | **订舱 / SI** | CI、PL 与 SI 一致 |
| 件数表述 | **packaging 计算 + SI** | `TOTAL n DRUMS PACKED ON m PALLETS ONLY.` |
| 毛重 / 体积 | **整柜=packaging 计算；散货=货代入仓** | 见 §5 |
| 批号 | **检测报告** | `SA` 前缀 |
| 生产日期 | **批号解析**（优先） | `SA+YYYYMMDD`，失败再标签 |
| 有效期 | **产品规则 / 人工** | 两套规则并存，不硬编码一种 |
| 含固量 / pH / 外观 | **检测报告** | pH 条件写法 **待确认** |
| HS Code | **PI > 知识库** | 与现网一致 |

#### 目的地三套口径（P1-6，必须转换，不能同串直搬）

| 用途 | 口径 | WA254 实际 | WA318 实际 |
|------|------|------------|------------|
| PI / 价格术语 | 贸易术语目的地 | `CIF KEELUNG基隆` | `CIF HOCHIMINH` |
| **CI / PL ROUTE** | `FROM POL TO {国家或地区}` | `FROM NANSHA, CHINA TO **TAIWAN, CHINA**` | `FROM NANSHA, CHINA TO **HOCHIMINH(CAT LAI),VIETNAM**` |
| **SI POL/POD** | 港口级 | `NANSHA,CHINA → **KEELUNG**` | `NANSHA,CHINA → **HOCHIMINH(CAT LAI),VIETNAM**` |

**转换规则（V2）**：

1. 起运港：默认 `NANSHA, CHINA`（可在 overrides / 客户模板覆盖）  
2. PI 目的地 → 规范化：复用 `core/destination_map.py`  
   - `normalize_destination_source`：中英混写取英文订舱用（`KEELUNG基隆 → KEELUNG`）  
   - `parse_destination` / `normalize_destination`：城市、国家拆分  
3. **SI POD** = 规范化后的港口英文（KEELUNG / HOCHIMINH(CAT LAI)）  
4. **CI/PL ROUTE TO** = 按客户模板的 `dest_style` 选择：  
   - `port`：与 SI 相同（WA318 型）  
   - `country`：`city → country`（WA254 型：KEELUNG → TAIWAN, CHINA）  
   - `custom`：模板内固定写法  
5. 未命中映射时 **保留原文并标黄待人工**，不瞎译

### 3.3 编号规则（维持 V1 判断：用 `IN` 不用 `IM`）

| 单据 | 编号 | 规则 | 样例 |
|------|------|------|------|
| PI | `HT…` | 业务既有 | `HT260720SZ` |
| CI | `IN` + 同后缀 | 前缀 `IN` | `IN260720SZ` / `IN260728A01` |
| PL | `PL` + 同后缀 | 前缀 `PL` | `PL260720SZ` / `PL260728A01` |
| COA | 无独立单号 | PI No + Batch No | 见 §TBD-2 |

**实现（P2-14）**：抽 `doc_no_service` 时 **原样保留** 现有 `_to_invoice_no` 幂等语义：

```text
_to_invoice_no (document_service.py:167)
  1. 空 → ""
  2. 已是 IN 开头 → 原样返回（幂等，禁止改成 PL 规则时丢掉）
  3. HT / HH / MH 前缀 → 替换为 IN，保留地区缩写
```

### 3.5 PL 装箱单（Packing List）

**= PI + 销售表数量 + packaging 计算 + SI（柜封号）**

| 区块 | 字段 | 来源 |
|------|------|------|
| 运输 | ROUTE / CONTAINER / SEAL | 同 CI（与 SI 一致） |
| 单头 | TO / PACKING NO. / PI NO. / DATE | PI；`PL`+后缀 |
| 明细 | ITEM 件号 | `item_no_mode: range(1-8) \| single(1)` |
| 明细 | DESCRIPTION | PI 品名 |
| 明细 | PACKAGE 列 | **`package_unit: pallets \| drums`**（WA318=托 8；WA254=桶 50） |
| 明细 | CBM / N.W. / G.W. | 见 §5 最终确认值 |
| 明细备注 | HS / PO# / 件数句 | 同 CI |
| 合计 | TOTAL | **生成时对扩展后的明细行统一写 `SUM(x_start:x_end)`**（P1-10：样例 F 列曾少算一行） |
| 落款 | 签名 | company_code |

#### 件数公式（P0-2 修正 —— 对齐 `packaging_service`，不是 ceil）

```text
drums        = ceil(数量_kg / 单桶净重_kg)          # 与包装计算器一致
full_pallets = drums // drums_per_pallet            # 整板数（floor）
remainder    = drums %  drums_per_pallet
pallets      = full_pallets + remainder_pallets(mode)

remainder_mode（已有三态，禁止重做）:
  full_pallet_merge       余数合并到 1 块共享余数板
  full_pallet_independent 每行余数各开 1 块余数板
  no_pallet               无托盘，只计桶自身

WA318: 4000/125=32 drums；32//4=8 full；remainder=0 → 8 PALLETS
WA254: 3000/60=50 drums；若每托 25 → 50//25=2 full；若按样例 3 托
       ⇒ 必须走「余数凑整板 / 独立余数板」或每托容量参数不同
```

**待确认（并入 §TBD-3）**：WA254 桶规格 `60kg/drum` 与「每托桶数」参数 —— 决定 `3` 是整板算出还是余数折出。**依据是船务部包装资料 Excel 表（Phase D 阻塞输入，Phase A 就去要）**。

**真实业务提醒（录音）**：人工会灵活拼尾数板（A 剩 3 桶 + B 剩 2 袋拼一托）。系统输出作 **建议值**，允许人工覆盖后再进四单。

## 5. 包装计算与实测覆盖（P0-1 / P0-2 重写）

> **V1 错误**：把现状说成 `calculation_service` + `pallets = ceil(...)`。  
> **事实**（已回源）：清关/包装业务真正走的是 **`backend/app/services/packaging_service.py`** + 前端 **`PackagingCalculator.vue`**。  
> `calculation_service.py` 只服务 `/packages` 接口，**不是**本期要「修好再复用」的主路径。

### 5.1 现状（复用，禁止回退）

| 能力 | 位置 | 语义 |
|------|------|------|
| 整板数 | `packaging_service.calculate()` `:280-283`、`calculate_single_product()` `:421-423` | `full_pallets = drums // drums_per_pallet`（**floor**），`pallets = full_pallets` |
| 余数 | `ProductPackagingResult.remainder` | `drums % drums_per_pallet` |
| 余数三模式 | `calculate_remainder_contribution()` `:557` | `full_pallet_merge` / `full_pallet_independent` / `no_pallet` |
| 前端三态 UI | `PackagingCalculator.vue` `:175-178` 等 | 默认 `full_pallet_merge` |
| 整单汇总 | `calculate_order_packaging()` `:453` + `PalletDetail` | **按卡板规格分组** |

历史依据：`docs/superpowers/plans/2026-06-14-remainder-allocation.md`、`2026-07-27-no-pallet-option-plan.md`。

**V2 约定**：

- **L1 整柜标准** → **复用现状**，不动 `pallets = full_pallets` 语义  
- **L3 人工装板方案** → **复用** PackagingCalculator 已有能力 / 仅做「方案写入台账」小扩展  
- **禁止**把 floor 改回 ceil，禁止重做三模式

### 5.2 真缺口（仅这两项是新增）

| 层级 | 内容 | 说明 |
|------|------|------|
| **L2 跨产品余数合托** | `calculate_order_packaging` 目前只**按规格分组**，**不做跨产品拼板** | 支持「A 剩 3 桶 + B 剩 2 袋 → 合 1 托」的建议方案；不改变单产品 floor 语义 |
| **L4 货代实测覆盖** | `shipment_measurements` **不存在** | 散货强制以货代入仓 CBM/G.W. 为准；一键导入/手填 **覆盖** L1/L2；清关四单只吃 **最终确认值** |

### 5.3 与四单的接口契约

```text
clearance 四单读取「shipment 打包结果」顺序：
  1) shipment_measurements(source=forwarder) 若已确认     ← 散货优先
  2) shipment_measurements(source=factory) 若已确认      ← 整柜
  3) packaging_service.calculate_order_packaging() 建议值  ← 可标「未实测」
用户可在生成前 overrides 覆盖 gross/net/cbm/packages/pallets
```

5. **脏 sheet / 旧单复制** → 只写干净实例。  
6. **xlsx only** → 禁止 `.xls` 模板与生成。  
7. **禁止回退包装计算**（P0-1）→ code review 对照 `full_pallets` 语义与三模式用例。

## 0. 一句话结论

在「单证生成工作流」的 **报关资料按钮右侧** 新增 **4 个清关文件按钮：提单补料 BL/SI、商业发票 CI、装箱单 PL、品质证书 COA**。  
全部以 **PI（合同表）为唯一数据源**，按 **客户编码加载定制模板** 自动填充；散货重量体积以货代入仓实测为准，整柜以工厂过磅/订舱计算为准。产地证、MSDS 不在本期范围。

## 1. 对接录音要点（已整理）

### 1.1 核心共识

| 要点 | 结论 |
|------|------|
| 原文件 / 源头 | **PI 合同表（Excel）**。PI 错，后面全错；一切以 PI 为准 |

## 2. 单据体系与对应关系

```text
                    ┌──────────────────┐
                    │  PI 合同表(源头)  │
                    │  Proforma Invoice│
                    └────────┬─────────┘
           ┌─────────────────┼─────────────────┬──────────────────┐
           ▼                 ▼                 ▼                  ▼
     ┌─────────┐       ┌─────────┐       ┌─────────┐        ┌─────────┐
     │ BL 提单 │       │ CI 发票 │       │ PL 箱单 │        │ COA 证书│
     │ 订舱补料│       │ 客户清关│       │ 装箱明细│        │ 品质证明│
     └────┬────┘       └────┬────┘       └────┬────┘        └────┬────┘
          │                 │                 │                  │
          │                 │                 ├─ 数量：销售表/订单│
          │                 │                 ├─ 件数：计算服务    │
          │                 │                 └─ 柜封号：BL       │
          │                 │                                    │
          │                 └─ 价格：PI 单价×数量                 │
          │                                                      │
          ├─ 整柜 CBM/毛重：工厂订舱计算+过磅                     │
          └─ 散货 CBM/毛重：货代入仓实测                          │
                                                                 │
                    品质部中文检测报告 ───────────────────────────┘
                    （含固量 / pH / 外观 等检测项 + 批号）
                    产品标签 ── 生产日期 / 有效期
```

### 2.1 数据源优先级

| 字段 | 权威来源 | 备注 |
|------|----------|------|
| 品名（英文） | **PI** | 一切以 PI 为准，不用检测报告中文名直译 |
| 数量 / 净重 | **PI / 销售表** | PL 的数量 PI 常不显示明细时取销售表 |
| 单价 / 金额 | **PI** | CI 金额 = 数量 × 单价；生成后可人工改 |
| 合同号 / PI No | **PI** | 形如 `HT260720SZ`、`HT260728A01` |
| 发票号 | 规则生成 | `IN` + 合同号去掉 `HT` 前缀后的后缀（见 3.2） |
| 装箱单号 | 规则生成 | `PL` + 同一后缀 |
| 收货人 / 通知人 | **PI** | 可在 Phase2 左栏覆写 |
| 发货人 | **公司配置** | 按发货人推导 `company_code`（宏昊/民浩） |
| 起运地 / 目的地 / 价格术语 | **PI** | 如 CIF HOCHIMINH / CIF KEELUNG |
| 柜号 / 封号 | **订舱 / BL** | CI、PL 与 BL 一致 |
| 件数表述 | **计算 + BL** | 如 `TOTAL 32 DRUMS PACKED ON 8 PALLETS ONLY.` |
| 毛重 / 体积 | **整柜=工厂计算；散货=货代入仓** | 见 2.2 |
| 桶数 / 卡板数 | **包装计算** | `ceil(数量/净重每桶)`、`ceil(桶数/每板容量)` |
| 批号 | **品质部检测报告 / COA 源** | 如 `SA20260626017` |
| 生产日期 / 有效期 | **产品标签** | COA 专用；录入或标签字段 |
| 含固量 / pH / 外观 | **检测报告** | 中→英翻译后填 COA |
| HS Code | **PI / 知识库** | PI > 知识库（与现有优先级一致） |

### 2.2 整柜 vs 散货（重量体积）— 必须分支

| 场景 | 体积 CBM | 毛重 G.W. | 净重 N.W. | 依据 |
|------|----------|-----------|-----------|------|
| **整柜（FCL / 工厂专柜）** | 订舱时工厂计算值 | 工厂过磅（带桶带托） | 货物净重 | 计算服务 + 过磅 |
| **散货（LCL / 拼箱）** | **货代入仓实测** | **货代入仓实测** | 货物净重 | 不得用工厂估算 |
| 混合 / 拼板尾数 | 以实际装柜方案为准，系统只做「建议」，允许人工覆盖 | 同左 | 同左 | 录音明确：灵活拼板无法穷尽 |

**净重 vs 毛重**：净重 = 货物本身；毛重 = 带桶 + 带卡板总重。

## 3. 四份清关文件填写逻辑（字段级）

> 模板原则：**只读模板 + 占位符 / 单元格映射填充**，禁止直接改模板文件（与现有 `references/*` 约定一致）。  
> 样式来源：以两套成品 xlsx 脱敏后制作「公共模板」；客户差异走客户模板。

### 3.1 PI（源头，系统内已有，不在本期 4 按钮内）

已有 Phase1 PI 上传/解析能力。本期只 **读取 PI 结果** 作为填充源，不重做 PI 编辑器。

关键字段：卖方抬头、Consignee Name/Address、Date、PO No、PI No、Description（含 HS）、Packing（如 125kg/drum）、Quantity、Unit Price、Amount、Remarks（包装/运输方式）、付款条款、受益人银行块、原产国、装运港。

### 3.2 编号规则（录音 + 样例交叉验证）

| 单据 | 编号 | 规则 | 样例 |
|------|------|------|------|
| PI | `HT` + 日期/流水 | 业务既有 | `HT260720SZ`、`HT260728A01` |
| CI | `IN` + **与 PI 同后缀** | 前缀 `IN` 固定；后缀 = PI 号去掉 `HT` | `IN260720SZ`、`IN260728A01` |
| PL | `PL` + **与 PI 同后缀** | 前缀 `PL` 固定 | `PL260720SZ`、`PL260728A01` |
| COA | 无独立单号 | 以 PI No + Batch No 标识 | PI `HT260728A01` + Batch `SA20260807038` |

实现：复用/扩展 `document_service._to_invoice_no()`，抽成 `doc_no_service`：

```text
pi_no = HT260720SZ
suffix = 260720SZ          # 去掉前缀 HT
invoice_no = IN + suffix   # IN260720SZ
packing_no = PL + suffix   # PL260720SZ
```

> 录音口述发票前缀像 “IM”，但成品样例一律是 **`IN`**。**以样例为准，用 `IN`。**

### 3.3 CI 商业发票（Commercial Invoice）

**固定块（公司级，随 company_code 切换）**  
卖方抬头三行（公司名/地址/TEL-FAX）→ 受益人银行 6 行 → 签章公司名。

**每单动态块**

| 区块 | 字段 | 来源 | 样例 |
|------|------|------|------|
| 运输 | TRANSPORT AND ROUTE | `FROM {装运港} TO {目的港}` | FROM NANSHA, CHINA TO HOCHIMINH(CAT LAI),VIETNAM |
| 运输 | CONTAINER NO. | BL/订舱 | WHLU5694625 |
| 运输 | SEAL NO. | BL/订舱 | WHA4051188 |
| 单头 | TO（客户名+地址+TAX CODE） | PI Consignee | CHEMZONE / JINTEX |
| 单头 | INVOICE NO. | `IN`+后缀 | IN260720SZ |
| 单头 | DATE | 制单日 | 2026-08-01 |
| 单头 | PI NO. | PI | HT260720SZ |
| 单头 | PRICE TERM | PI | CIF HOCHIMINH / CIF KEELUNG |
| 明细 | ITEM | 序号 | 1 |
| 明细 | DESCRIPTION | PI 品名（可带 QTY/HS 行） | FIXING AGENT HT-016H |
| 明细 | QUANTITY (KGS) | PI 数量 | 4000 |
| 明细 | CIF PRICE (USD) | PI 单价 | 2.6 |
| 明细 | AMOUNT (USD) | =数量×单价（公式） | 10400 |
| 明细备注 | HS CODE | PI/知识库 | 340241 |
| 明细备注 | 包装件数句 | 计算+BL | TOTAL 32 DRUMS PACKED ON 8 PALLETS ONLY. |
| 付款 | PAYMENT TERMS | PI/客户模板 | 100% TT AFTER SHIPMENT 30 DAYS |
| 合计 | TOTAL 数量/金额 | SUM 公式 | 4000 / 10400 |
| 合计 | 大写金额英文 | 金额转英文 | TOTAL USD TEN THOUSAND... |
| 落款 | 公司签名栏 | company_code | HONGHAO CHEMICAL CO., LTD. |

**客户定制点**（常见）：银行块行数、是否显示 TAX CODE、是否加 PO#、单位列是否独立（KG）、价格术语拼写、备注行（QTY/HS 写法）、签字布局。

### 3.4 PL 装箱单（Packing List）

PL **= PI + 销售表（数量明细）+ 计算（件数/体积/重量）+ BL（柜封号）**。

| 区块 | 字段 | 来源 | 样例 |
|------|------|------|------|
| 运输 | ROUTE / CONTAINER / SEAL | 同 CI（与 BL 一致） | 同左 |
| 单头 | TO | PI Consignee | 同 CI |
| 单头 | PACKING NO. | `PL`+后缀 | PL260720SZ |
| 单头 | PI NO. / DATE | PI / 制单日 | HT260720SZ |
| 明细 | PACKING NO.（件号） | 1 或 1-8 | `1-8`（托盘段号）或 `1` |
| 明细 | DESCRIPTION | PI 品名 | 同 CI |
| 明细 | PACKAGE(S) / PACKING QTY | **桶数或托数（客户模板不同）** | WA318=`8`（PALLETS）；WA254=`50`（PACKAGES=drums） |
| 明细 | PACKING SIZE (CBM) | 体积（整柜算/散货货代） | 7.92 / 6.06 |
| 明细 | NET WEIGHT (KG) | PI 净重 | 4000 / 3000 |
| 明细 | GROSS WEIGHT (KG) | 毛重（带桶带托） | 4308 / 3261 |
| 明细备注 | HS CODE / PO# / 件数句 | 同 CI | 同左 |
| 合计 | TOTAL 行 | SUM 公式 | 同明细 |
| 落款 | 公司签名 | company_code | 同 CI |

**件数计算逻辑（与现有 `calculation_service` 对齐）**

```text
drums   = ceil(数量_kg / 单桶净重_kg)          # 例：6000/125=48→或 4000/125=32
pallets = ceil(drums / 每托桶数)              # 例：32/4=8
体积    = drums × 桶体积 + pallets × 托体积
毛重    = drums × 桶毛重 + pallets × 托重
件数句  = "TOTAL {drums} DRUMS PACKED ON {pallets} PALLETS ONLY."
```

WA318 样例：4000kg ÷ 125kg/drum = **32 drums**；**8 pallets**；CBM **7.92**；G.W. **4308**；N.W. **4000**。  
WA254 样例：3000kg ÷ 60kg/drum = **50 drums**；**3 pallets**；CBM **6.06**；G.W. **3261**；N.W. **3000**。

**注意**：WA318 工作簿里残留一张旧客户 sheet（MAXCRUDE / HT20171108），说明业务靠「复制旧单改数」——系统必须 **按模板干净生成**，禁止整本复制旧单残留。

**客户定制点**：PACKAGE 列含义（托 vs 桶）、是否有 PO# 行、是否显示 CBM、件号是否 `1-8` 段号、签名位置。

### 3.5 COA 品质证书（Certificate of Analysis）

**源 = 品质部中文检测报告（+标签日期）+ PI 品名数量**。只翻检测核心项，不整篇机翻。

| 区块 | 字段 | 来源 | WA318 样例 | WA254 样例 |
|------|------|------|------------|------------|
| 抬头 | 公司 3 行 | company_code | HONGHAO… | HONGHAO… |
| 标题 | CERTIFICATE OF ANALYSIS | 固定 | 同 | 同 |
| 品名 | PRODUCT NAME / NAME OF PRODUCT | **PI 品名** | FIXING AGENT HT-016H | WET RUBBING… WRF HT825G |
| 批次 | Batch No. | 检测报告批号 | SA20260626017 | SA20260807038 |
| 数量 | Shipped Quantity / QUANTITY | PI 数量 | 3250KG | 3000kg |
| 日期 | Manufacture / Expiry | **产品标签** | 2026-06-26 / 2027-06-25 | 2026-08-07 / 2027-02-06 |
| 感官 | APPEARANCE 外观 | 检测报告 | Yellow transparent mucus | Yellow transparent mucus |
| 感官 | ODOUR 气味（可选） | 检测报告 | （无此行） | Slight odour |
| 理化 | SOLID CONTENT 含固量 | 检测报告 | 70±2 → 70.72 | 32±1 → 32.39 |
| 理化 | PH / PH VALUE | 检测报告 | PH(1%) 6.5~7.5 → 7.3 | PH VALUE(20%) 4±0.5 → 3.79 |
| 理化 | 其他（粘度/糖度等，可选） | 检测报告 | — | — |
| 结论 | CONSEQUENCE | **固定文案** | GB/T19001… | 同 |
| 落款 | MAKER / QUALITY CENTER | **固定文案** | 同 | 同 |

**翻译项映射（中文检测报告 → 英文 COA）**

| 中文检测项 | 英文 COA 行 | 默认规格写法 |
|------------|-------------|--------------|
| 外观 | APPEARANCE | 直译外观描述 |
| 含固量（%） | SOLID CONTENT / SOLID CONTENT(%) | `70±2` / `32±1` |
| 1%pH值 / 50g/L pH值 / pH | PH (1%) / PH VALUE (20%) / PH | 按报告条件写 |
| 气味 | ODOUR（可选） | Slight odour |
| 粘度 / 糖度 等 | VISCOSITY / BRIX 等（按需加行） | 有则填，无则整行省略 |

**固定不改块**：标题、CONSEQUENCE、MAKER、THE CENTER OF QUALITY INSPECTION、公司落款。  
**批次多页**：一票多批 → 一 batch 一 sheet（WA318 两批号 × 双 sheet，业务还会复制 2 份）。系统应支持 **一批一 sheet / 一键多批生成**。

**客户定制点**：检测项行数（有的多气味行、有的只含固量+pH）、`PH (1%)` vs `PH VALUE (20%)` 条件写法、字段标签拼写（NAME OF PRODUCT vs PRODUCT NAME）、是否带 PI No 行。

### 3.6 BL 提单 / 订舱补料（SI）

录音定位：**即订舱用的补料（SI）**，格式 **随船公司变**。本期策略：

1. **公共字段自动填充**（发货人 / 收货人 / 通知人 / 品名 / 件数 / 净毛重 / 体积 / HS / 柜封号 / 运输路线）；  
2. **船公司格式做「客户/船司模板」**（与客户模板同一套机制，绑定键可以是 `customer_code` 或 `carrier_code`）；  
3. 若某船司暂无模板 → 生成「字段齐全的标准补料单」，人工粘贴到船司格式。

## 4. 客户定制模板机制（开发核心）

### 4.1 问题

统一公共模板 → 每单大量手改 → 用着用着弃用 → 回到纯手工（录音领导原话风险）。

### 4.2 方案：公共模板 + 客户模板两级

```text
选择订单/台账
    → 读取 customer_code（系统已有识别）
        ├─ 命中 customer_templates[customer_code][doc_type]
        │       → 用客户模板填充
        └─ 未命中
                → 用公共模板 + 标准字段集填充
                    → 生成后用户微调（OnlyOffice）
                        →【另存为该客户模板】
                            → 下次自动命中
```

### 4.3 数据模型（建议）

```text
customer_templates
- id
- customer_code          -- 如 WA318 / WA254
- doc_type               -- bl | ci | pl | coa
- company_code           -- honghao | minhao（抬头/印章）
- template_blob          -- xlsx 模板（脱敏）
- field_map_json         -- 占位符 → 单元格映射；可覆盖默认
- item_row_start/end     -- 明细行扩展区
- options_json           -- PACKAGE 列语义(托|桶)、是否显示 PO#、检测项行开关等
- version / is_active / created_by / created_at

template_fill_log（可选，审计）
- order_id / ledger_id / customer_code / doc_type / template_id / operator
```

### 4.4 填充技术路线（与现有 OnlyOffice 链路一致）

1. 读模板 xlsx bytes（openpyxl）  
2. **占位符替换**（复用 `replace_placeholder` / `find_marker_cell`）或 **cell map 写值**  
3. 明细行按产品数扩展（复用 `_extend_*_sheet` 思路）  
4. 公式列（Amount、TOTAL）可保留 Excel 公式，由 OnlyOffice 计算  
5. 返回 bytes → `DocumentService` 存 `shipment_docs` → `OnlyOfficeService` 出编辑 config  
6. 用户在 OnlyOffice 微调 → callback 落库 → **可「存为模板」**

## 5. 重量体积计算修复（散货）— 并行必做

录音指出：现有包装计算 **整柜对、散货灵活拼板错**，导致报关单数量不准、计算功能几乎无人用（只有 MSDS 在用）。

### 5.1 现状问题

`calculation_service` 目前是理想整除：

```text
pallets = ceil(drums / capacity_per_pallet)
```

真实仓库会：

1. 多产品 **尾数拼板**（A 剩 3 桶 + B 剩 2 包 → 拼 1 卡板）  
2. **部分打卡板**（100 桶里 50 桶上托，50 散装）  
3. **不同包装混装**（粉袋 + 吨桶拼托）  
4. 最终以 **货代入仓实测** 覆盖

### 5.2 修复方向

| 层级 | 做法 |
|------|------|
| L1 整柜标准 | 保持现有 `ceil` 公式，结果作「建议值」 |
| L2 拼板建议 | 新增「混合尾数拼板」算法：同规格优先满板；异规格尾数允许合托（可配置每托体积/承重上限） |
| L3 人工方案 | 包装计算器增加 **「实际装板方案」编辑**：每板装载行（产品、桶数、净毛重、体积），系统汇总 |
| L4 外部实测覆盖 | 散货强制以货代入仓 CBM/G.W. 为准，可一键导入/手填 **覆盖** L1/L2 |
| 数据落库 | `packaging_scheme`（装板明细）+ `shipment_measurements`（实测来源：factory / forwarder） |

**清关四单只消费最终确认的净毛重/体积/件数**，不直接吃未确认的理想计算。

## 10. 风险与约束

1. **价格与个人信息**：CI/PI 含单价、银行账号、客户税号。入库模板需脱敏；生产数据权限沿用现有用户体系；外发导出需审计（录音明确要求保密）。  
2. **PI 格式不统一**：必须在 Phase1 PI 解析后 **归一到系统字段**，禁止直接吃业务员原格式。  
3. **散货实测滞后**：先生成后回填，避免用错估算值出提单。  
4. **客户模板爆炸**：以 `customer_code + doc_type + company_code` 为键；先公共模板跑通，再逐客户沉淀。  
5. **旧单复制残留**（样例已出现脏 sheet）：系统生成必须干净模板实例。  
6. **All docs xlsx only**：xls 一律转换后再用；新模板禁止 `.xls`。  
7. **HARD-GATE**：本文件为设计/方案，**批准前不写实现代码**（项目 AGENTS.md 约定）。
